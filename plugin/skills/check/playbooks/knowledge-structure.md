# Knowledge structure

## Use this playbook when

Use it when cards, nodes, modules, hierarchy, card size, domain fields, or progress mappings look wrong.

## Procedure

1. Load the domain contract before judging card contents.
2. Check stable IDs, module hierarchy, domain card types, required fields, atomicity, and duplicate concepts.
3. Check that full questions are referenced rather than copied into cards.
4. Check knowledge mastery separately from question mastery.
5. Emit findings with repairOwner learn/knowledge-structure or the domain model, such as study-math.

## Gate

Use the domain model's own Card Schema. Do not report a mathematical Card Type as an error in a non-math Subject.
