# 中式学生：检查指令

## 目标

检查不是简单确认“文件存在”。它要证明：当用户看到或想到一个知识点时，能立即找到对应的唯一知识卡，并能在卡中看到足够的知识内容、重点、题目和关系。

检查默认只读。除非用户明确要求修复，否则不要修改 Markdown、HTML、学习状态或题目记录。

## 检查输入

1. 定位一个学科的 canonical Markdown、唯一网络图 HTML、项目状态文件和学习状态文件。
2. 读取图谱的实际节点数据和渲染页面，不只读取文件名或项目自报结果。
3. 建立检查清单和概念探针。探针来自：
   - 主知识点卡标题；
   - 关联知识点卡标题；
   - 原文中的核心术语；
   - 相关题目中的考查知识点；
   - 章节哈希表中的章节键和别名。

## 必查项目

### 1. 卡片范围

- 每个学科只有一个网络图 HTML。
- 所有节点只能是 `主知识点卡` 或 `关联知识点卡`。
- 不得出现以“细节”“补充碎片”“局部说明”等形式绕过主卡/关联卡约束的节点。

### 2. 立即定位

对每个概念探针分别做精确标题、关键词、同义表达和章节搜索：

- 找不到卡：`缺失`；
- 找到多个语义相同的卡：`重复/歧义`；
- 只能靠不稳定的全文偶然命中：`索引不足`；
- 唯一定位到正确卡：`通过`。

把每个失败探针记录为：查询词、期望知识点、实际命中、失败原因和建议修复位置。

### 3. 主卡内容

每个主知识点卡必须包含：

- `知识内容`：原文、课本内容或明确标注来源的补充解释；
- `从内容提取出来的重点`：读完知识内容和相关题目后直接提炼，不得机械拆句；
- `相关的题目`：题目、自己的解答思路、官方答案、考到的知识点；
- `关联的知识点`：稳定 ID、标题和关系理由。

关联知识点卡也必须包含同样的四个区块，但可以通过关系链进入；不得把它变成没有完整内容的细节卡。

### 4. 内容与证据

- 原始图片/课本内容、外部补充、题目推导、官方解析可读部分和待核实内容必须分开标记。
- PDF 截断或不可读的内容不得被当成官方答案。
- 相关题目不能只有题号、公式和答案，必须有可迁移解题思路。
- 选择题和填空题如果有提速方法，必须同时有通解、适用条件和失效边界。

### 5. 格式与渲染

- Markdown 文本结构正确。
- 数学公式使用真正的 LaTeX 定界符，并通过 `scripts/validate_markup.py`。
- HTML 中 Markdown、LaTeX、中文、关系边和题目卡实际可读。
- 搜索、节点点击、关系跳转和窄屏布局至少各检查一次。

### 6. 学习完成状态

- 检查学习依赖闸门：来源覆盖、概念清晰、题目准备、关系完整、公式可读、主动缺口已记录。
- 任一项目失败，报告 `学习未完成`，并把它作为未来考试的 `图谱缺口`。
- 全部通过后，才报告 `可用于考试`。

## Eval-style 证据要求

正式检查要像一次可重复的行为检查：

1. 先写 3–6 条具体通过标准，不用“看起来完整”这类空标准。
2. 用同一组概念探针对当前图谱做完整检查，不根据自报结果打分。
3. 每条失败都附文件、节点 ID、查询词或渲染位置。
4. 检查结束后再给出通过/未通过结论；不要在检查过程中悄悄修复并把修复结果冒充原始质量。

最终报告包含：检查范围、通过项、失败项、定位证据、学习状态和修复建议。
