# 数学公式与渲染检查

## 来源与输出

结构化记录保存原子 MathObject 和结构信息；canonical Markdown 用带定界符的 LaTeX 输出；HTML 使用项目既有 MathJax/KaTeX/MathML/SVG 渲染方式。不要把纯文本 `frac`、丢失的选项或空白节点当成成功。

必须保留：

```text
分子/分母
根号覆盖范围
积分上下限
求和上下标
矩阵行列
括号范围
上下标归属
分段条件
微分方程阶数与初值/边界条件
```

## Markup validator

`study-math/scripts/validate_markup.py` 检查 Markdown 或报告中的：

- `$$...$$`、`\\[...\\]`、`\\(...\\)` 和单美元定界符是否成对；
- 代码块和行内代码是否被正确屏蔽；
- `\\frac`、`\\sqrt`、`\\lim`、希腊字母等 LaTeX 命令是否错误地出现在数学定界符外；
- 常见括号组是否闭合。

它不替代浏览器渲染检查：定界符通过不等于公式实际可读。

## 实际渲染检查

完成后打开真实 HTML，至少检查：

1. 函数极限定义、Lagrange 条件/结论、比值判别公式、递推数列决策树和 Bridge 关系；
2. 长分式、矩阵、积分上下限、分段函数和中文混排；
3. 卡片选择、搜索、关系跳转、窄屏布局和“查看全部相关题目”；
4. 浏览器 console、资源路径和公式渲染错误。

如果源公式不可读，页面必须显示“数学表达式无法核实”或对应状态，而不是空白。
